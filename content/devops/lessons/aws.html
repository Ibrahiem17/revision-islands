🛡️ High Availability vs Disaster Recovery
High Availability (HA)
Cluster is always accessible even if one or more servers are down. Achieved by:
• Multi-AZ deployment within a region
• Redundant instances + auto-scaling
• Load balancers routing around failed nodes
Disaster Recovery (DR)
Continue service even during a regional outage. Achieved by:
• Multi-region deployment
• Data replication across regions
• DNS failover to backup region
🌐 AWS Networking Summary
VPCisolation
Virtual Private Cloud — your isolated network. Resources (EC2, RDS) live inside subnets within the VPC. Public subnets face internet. Private subnets are internal only.
Security Groupsfirewall
Virtual firewall. Controls inbound/outbound traffic by port, protocol, source IP. Stateful — if you allow inbound, outbound response is auto-allowed.
Load Balancer (ALB)traffic
Distributes HTTP(S) traffic across multiple instances. Health checks remove unhealthy instances. Path-based routing. SSL termination.
IAMaccess control
Least privilege principle: Give only the permissions needed. IAM Roles attach to EC2/Lambda — never hardcode access keys in code. Use roles for service-to-service auth.

🌐 Global Infrastructure — Regions & AZs
🌍 Regions
Geographic locations around the world — us-east-1 (N. Virginia), eu-west-1 (Ireland), ap-southeast-1 (Singapore). Each is a massive cluster of data centers.

Choose your region based on: latency to users, data residency laws, and service availability.
🏢 Availability Zones (AZs)
Within each Region there are multiple physically isolated data centers: us-east-1a, us-east-1b, us-east-1c. Independent power, cooling, networking.

If a disaster hits one AZ, the others stay online. Good DevOps = always deploy across 2+ AZs.

⚖️ L4 vs L7 Load Balancers (NLB vs ALB)
⚡ L4 — NLB (Fast, Blind)
Only looks at the IP address and TCP/UDP port. Has no idea what the user is asking for. Just grabs the packet and sends it to the next server as fast as possible.

Pros: Blazing fast, low latency, millions of req/sec.
When to use: Raw speed matters, or non-HTTP traffic (gaming servers, database connections).
AWS = NLB (Network Load Balancer)
🧠 L7 — ALB (Smart, Reading)
Opens the packet and reads the HTTP request. Understands the request content and can make smart routing decisions.

Path-based routing: /images → Image Servers. /api → API Servers.
When to use: Web apps and microservices routing by URL, headers, or cookies.
AWS = ALB (Application Load Balancer)
🏗️ VPC Architecture — Step by Step
Golden rule: Never put a database on the public internet. Design a network that separates public-facing traffic from secure backend resources.
1
Create the VPC
Create a Virtual Private Cloud with a CIDR block like 10.0.0.0/16. This is your isolated slice of AWS — nothing gets in or out without your permission. Use /16 for enough IPs for all subnets.
2
Carve out Subnets
Public Subnet 10.0.1.0/24 → Web server / Load Balancer lives here.
Private Subnet 10.0.2.0/24 → Database lives here. Repeat in each AZ for HA.
3
Attach Internet Gateway (IGW)
A VPC is completely locked down by default. Attach an IGW to give the public subnet internet access. Think of it as the modem for your cloud network. Private subnet gets no IGW route — stays safely offline.
4
Security Groups (Bouncers)
Web SG: Allow port 80/443 from internet (0.0.0.0/0).
Interview Gold: DB SG — allow port 3306 only from the Web Security Group ID, not from an IP. Only instances wearing the "Web SG badge" can talk to the DB. Never open the DB to 0.0.0.0/0.
5
Launch EC2 + User Data
Select AMI (Amazon Machine Image — the OS blueprint, e.g. Ubuntu 22.04), choose instance type (t3.micro), place in correct subnet. User Data = a bash script that runs on first boot. Use it to automatically apt install nginx — no SSH needed. This is bootstrapping.
Your DevOps job: automate all of this in Terraform.
6
NAT Gateway (Private → Internet)
Private subnet resources (app servers, DBs) can't reach the internet directly. A NAT Gateway in the public subnet allows outbound internet access (for package updates, API calls) without exposing the private resources to inbound traffic.
Architecture diagram:
Internet → IGW → ALB (public subnet) → App servers (private subnet) → RDS (private subnet)
Private subnet → NAT Gateway (public subnet) → IGW → Internet (for outbound only)

📡 CDN — Content Delivery Network
A CDN caches static assets (images, JS, CSS, HTML) at edge locations globally. When a user requests a file, it's served from the nearest edge location — not from your origin server.

Benefits: Dramatically reduces latency (user in Singapore gets content from Singapore edge, not your US server). Reduces origin server load. Protects against traffic spikes.

AWS CloudFront (AWS CDN), Cloudflare, Fastly are the major players.

DevOps gotcha: After a deployment, CDN may serve stale cached files. You need to invalidate the cache or use cache-busting (e.g., hashed filenames like app.a3f9d2.js).
🔒 Firewall vs Reverse Proxy
🛡️ Firewall
Controls which traffic is allowed into/out of a network based on rules (IP, port, protocol). Does NOT see the content of requests — just the "envelope". AWS Security Groups and NACLs are firewalls.
🔀 Reverse Proxy
Sits in front of servers and forwards client requests to them. Reads the request content. Used for: load balancing, SSL termination, caching, hiding backend topology. Nginx is often both. ALB acts as L7 reverse proxy.
📊 SLI / SLO / SLA
TERMFULL NAMEWHAT IT IS
SLIService Level IndicatorA measurable metric. Examples: error rate, p99 latency, uptime percentage. The raw number you track.
SLOService Level ObjectiveA target for an SLI. "99.9% of requests complete in under 200ms." Internal goal. If you miss SLOs, your error budget is consumed.
SLAService Level AgreementContractual commitment with customers. "We guarantee 99.9% uptime or you get a credit." SLOs are internal targets. SLAs are external promises with financial consequences.

🌐 Route53 — AWS DNS
AWS's highly available DNS service. More than just DNS — it also does health-based routing: if your primary server goes down, Route53 detects the health check failure and automatically reroutes traffic to a backup server or region.

Routing policies:
Simple — one record, one IP. Basic.
Weighted — 70% traffic to us-east-1, 30% to eu-west-1. Good for canary deploys.
Latency — route to the region with lowest latency for that user.
Failover — primary/secondary. If primary fails health check, Route53 switches to secondary. Core of disaster recovery.
Geolocation — route EU users to EU servers, US users to US servers.
📦 ECR — Elastic Container Registry
AWS's private Docker image registry. Like Docker Hub but inside your AWS account.

Key benefits: Integrated with IAM (control who can push/pull), no bandwidth cost for images pulled by ECS/EKS in same region, image vulnerability scanning built-in, lifecycle policies to auto-delete old images.
# Authenticate Docker to ECR (run before push/pull):
aws ecr get-login-password --region us-east-1 | docker login \
  --username AWS --password-stdin 123456789.dkr.ecr.us-east-1.amazonaws.com

# Tag and push:
docker tag myapp:v2 123456789.dkr.ecr.us-east-1.amazonaws.com/myapp:v2
docker push 123456789.dkr.ecr.us-east-1.amazonaws.com/myapp:v2
⏱️ RTO & RPO — Disaster Recovery Targets
RTO — Recovery Time Objective
How long can the system be down?
"After a disaster, we must be back online within 4 hours." This drives decisions about hot standby (minutes) vs cold backup (hours). Lower RTO = more expensive infra.
RPO — Recovery Point Objective
How much data can we afford to lose?
"We can tolerate losing up to 1 hour of data." This drives backup frequency. RPO = 1 hour → backups every hour. RPO = 0 → real-time replication required.
💬 SQS & SNS — Messaging Services
SQS — Simple Queue Service
Message queue. Producer sends message to queue. Consumer polls queue and processes it. Decouples services — if consumer is slow or down, messages wait in the queue. Use for: background jobs, order processing, task workers.
SNS — Simple Notification Service
Pub/Sub messaging. One publisher sends to a topic, many subscribers receive it simultaneously. Use for: fan-out (one event triggers multiple actions), sending emails/SMS, triggering Lambda functions.
