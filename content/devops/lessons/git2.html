🌿 Git Topics Interviewers Love to Test
git cherry-pickcopy 1 commit
Apply a specific commit from another branch to your current branch — without merging the whole branch. Used to backport a bug fix from main to a release branch without pulling everything else in.
$ git cherry-pick a3f9d2c $ git cherry-pick a3f9..b1e8 # range
git rebase -i HEAD~Nsquash/reorder
Interactive rebase — lets you squash, reorder, edit, or drop commits before pushing. Use to clean up messy WIP commits into one clean commit before opening a PR. Never rebase shared branches.
$ git rebase -i HEAD~5 # change 'pick' → 'squash' to combine
git tagreleases
Mark specific commits as releases. git tag v2.0.0 = lightweight tag. git tag -a v2.0.0 -m "msg" = annotated (includes tagger, date, message — use this). Push tags separately: git push origin v2.0.0.
$ git tag -a v2.0.0 -m "Release 2.0.0" $ git push origin --tags
git blamewho wrote it
Shows who last modified each line of a file, with the commit hash and date. Used to find who introduced a bug or who to ask about a piece of code. Not for blame — for context.
$ git blame src/auth.js # → shows author + commit per line
git diffsee changes
git diff = unstaged changes vs last commit. git diff --staged = staged changes. git diff main..feature = what's different between branches. Useful before every commit to review what you're shipping.
git cleanremove untracked
Remove untracked files and directories. git clean -fd = force-remove files and directories. Use when you want a completely clean working directory. Cannot be undone.
$ git clean -n # dry run (preview) $ git clean -fd # actually delete ⚠️
.gitignoreexclude files
Tells Git which files/directories to never track. Essential patterns: node_modules/, .env, *.log, dist/, .terraform/, *.tfstate. Add .gitignore as the first commit in any repo.
.env # never commit secrets! node_modules/ *.log .terraform/
Monorepo vs Polyreporepo strategy
Monorepo — all services in one Git repo. Easier cross-service refactoring, shared tooling. Used by Google, Meta. Polyrepo — each service in its own repo. Full independence, simpler pipelines per service. Most common in smaller orgs.
⚙️ Conventional Commits — The Standard Format
# Format: type(scope): description
feat(auth): add JWT token refresh      # new feature
fix(api): handle null user gracefully   # bug fix
chore(deps): bump axios to 1.4.0       # dependency update, no code change
docs(readme): add deployment guide     # documentation only
refactor(db): extract query builder     # no behavior change
ci(pipeline): add staging deploy step   # CI/CD changes
BREAKING CHANGE: remove v1 API         # triggers major version bump
