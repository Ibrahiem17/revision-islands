🚀 Deployment Strategies
Rolling Deploy
Take one server out of rotation, update it, add back. Repeat for each server. No downtime but there's a brief period running two versions simultaneously.

✅ Simple, safe. ⚠️ Brief version mismatch.
Blue / Green
Two full environments. LB routes to green (live). Deploy to blue. Test blue. Flip LB to blue. Rollback = flip LB back instantly.

✅ Instant rollback. ⚠️ Double infra cost.
Canary
Route 5% of traffic to new version via weighted rules. Monitor errors/latency. Expand % if healthy. Limits blast radius — if it breaks, only 5% of users affected.

✅ Safe for high-risk changes. ⚠️ More complex setup.
A/B Testing
Route users by header/cookie to different versions. Like canary but measuring user behavior, not just errors. Used to test feature impact on metrics (clicks, conversions).
⚖️ Load Balancing Algorithms
ALGORITHM HOW IT WORKS BEST FOR
Round Robin Req 1 → A, Req 2 → B, Req 3 → C, repeat. Evenly distributed. Stateless apps, equal server capacity
Least Connections Route to server with fewest active connections. Smarter than round robin. Requests vary in duration (some slow, some fast)
IP Hash Same client IP always hits same server. Deterministic routing. Sticky sessions when state isn't centralized
Weighted Server A gets 70%, Server B gets 30%. You define the ratio. Different server capacities, canary deployments
⚙️ How to Set Up a CI/CD Pipeline from Scratch
1
Set up CIJenkins / GitLab CI / GitHub Actions
Select a CI tool and connect it to your VCS. Write a build script: code checkout → dependency install → compile → run tests. Set up automated testing on every commit or PR.
2
Artifact StorageDocker Hub / AWS S3 / ECR
Decide where to store build artifacts (Docker images, binaries). Configure the pipeline to package and upload artifacts to storage after a successful build.
3
Set up CDSame tool or extend
Define deployment scripts for each environment (dev → staging → prod). Configure triggers after successful builds. Set up environment-specific configs and secrets management.
4
InfrastructureTerraform / CloudFormation
Provision infrastructure using IaC. Ensure environments are consistent and reproducible — spinning up a new one should be a single command, no human intervention.
5
Monitoring & LoggingPrometheus / Grafana / ELK
Implement monitoring for apps and infrastructure. Configure alerts for critical issues — monitoring without alerting is pointless, you need to react to problems.
6
Security & DocsSnyk / OWASP
Integrate security scanning tools (Snyk, OWASP). Document the pipeline, configuration, and deployment steps — to onboard new team members and maintain the system.
🕸️Service MeshIstio / Linkerd
A service mesh is a dedicated infrastructure layer for handling service-to-service communication in microservice architectures.

As your microservice count grows, orchestrating reliable communication between them becomes complex — load balancing, retries, timeouts, encryption, observability. A service mesh handles all this automatically, without changing your application code.

Think of it as a network of sidecar proxies attached to each service, intercepting all traffic and adding observability, security (mTLS), and routing capabilities.
