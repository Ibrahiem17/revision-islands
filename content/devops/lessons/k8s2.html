📦 More Kubernetes Objects
OBJECTWHAT IT DOES
DaemonSetEnsures one pod runs on every node. Used for cluster-wide agents: log collectors (Fluentd), monitoring agents (Prometheus node-exporter), network plugins (CNI). New node added → DaemonSet pod automatically scheduled on it.
JobRuns a pod to completion — not continuously. Once the pod succeeds (exit 0), the Job is done. Use for: database migrations, batch data processing, one-off scripts.
CronJobCreates Jobs on a cron schedule. Like Linux cron but in Kubernetes. Use for: nightly DB backups, periodic cleanup, scheduled reports.
NetworkPolicyFirewall rules for pod-to-pod traffic. By default, all pods can talk to all pods. NetworkPolicy restricts this. "Only the API pods can reach the DB pods." Requires a CNI plugin that supports it (Calico, Cilium).
PodDisruptionBudgetGuarantees minimum available pods during voluntary disruptions (node drain, cluster upgrade). "At least 2 replicas must stay running during maintenance." Prevents downtime during K8s upgrades.
ResourceQuotaLimits total resources (CPU, memory, pod count) consumed by all pods in a namespace. Prevents one team's workload from starving another's in a shared cluster.
📏 Resource Requests vs Limits
requests
The minimum guaranteed resources. The Scheduler uses this to decide which node the pod goes on. "I need at least 250m CPU and 256Mi RAM to run."
limits
The hard maximum. If the container exceeds the memory limit → OOMKilled. If it exceeds CPU limit → throttled (slowed down, not killed). Always set both.
resources:
  requests: { cpu: "250m", memory: "256Mi" }
  limits:   { cpu: "500m", memory: "512Mi" }
🏷️ Taints & Tolerations + Node Affinity
Taints & Tolerations
Taint a node = "repel all pods unless they tolerate this." Use to dedicate nodes: "only GPU workloads on GPU nodes."

kubectl taint nodes gpu-node gpu=true:NoSchedule
Add a matching toleration to the pod spec to allow it on that node.
Node Affinity
Pull pods toward certain nodes (vs taints which push pods away). Use to place pods on specific node types (SSD nodes, spot nodes, high-memory nodes) based on node labels.

requiredDuringScheduling... = hard rule.
preferredDuringScheduling... = soft preference.
🔄 Init Containers & Sidecar Containers
Init Containers
Run to completion before the main container starts. Used for: waiting for a DB to be ready, downloading config files, running DB migrations. If init container fails → main container never starts.
Sidecar Containers
Run alongside the main container in the same pod. Shared network and storage. Used for: log shippers (Fluent Bit), service mesh proxies (Envoy/Istio), secret injection.
⌨️ More Essential kubectl
kubectl top pods -n production     # live CPU/memory usage per pod
kubectl top nodes                  # live CPU/memory usage per node
kubectl get events --sort-by=.lastTimestamp # recent cluster events
kubectl drain <node> --ignore-daemonsets # evict all pods from node (maintenance)
kubectl cordon <node>                # mark node unschedulable (no new pods)
kubectl uncordon <node>              # re-enable scheduling
kubectl get pod <name> -o yaml       # full YAML of running pod
kubectl edit deployment myapp         # live-edit (opens vim, saves = applies)
kubectl diff -f deploy.yaml           # preview changes before apply
kubectl rollout history deploy/myapp   # list all revisions
