🔄 GitOps — Declarative Delivery
🌿GitOpsArgoCD / FluxCD
GitOps is an operating model where Git is the single source of truth for both application code AND infrastructure configuration. Everything is in Git — including Kubernetes YAML manifests.

A GitOps tool (like ArgoCD or FluxCD) continuously watches your Git repo. The moment you merge a change to the deployment manifests, the tool automatically syncs the Kubernetes cluster to match. If someone manually changes something in the cluster (drift), the tool detects it and reconciles back to what's in Git.

Pull-based model: Instead of your CI pipeline pushing to K8s, the cluster pulls its desired state from Git. More secure — no external write access to your cluster needed.
Git = single source of truthauto-sync to clusterdrift detection + reconciliationpull-based = more secure
🔐 Secrets Management
NEVERhardcoded
Never store secrets (API keys, DB passwords, tokens) in code or Git. Even in private repos. Attackers scan GitHub constantly. One leaked secret = full breach.

DB_PASSWORD="abc123" in code = fired in prod.
AWS Secrets Managercloud native
Store secrets in AWS. EC2/Lambda fetches them at runtime via SDK. Automatic rotation. Audit trail. IAM controls who can access which secret.
HashiCorp Vaultmulti-cloud
Cloud-agnostic secrets engine. Dynamic secrets (generates temp DB creds). Encryption as a service. Works across AWS, Azure, GCP, and on-prem.
K8s Sealed Secretskubernetes
Encrypt K8s Secrets so they're safe to commit to Git. Only the cluster can decrypt them. Solves "how do I store K8s secrets in Git safely?"
CI/CD Secretspipelines
GitHub Actions: store in Settings → Secrets. Access as ${{ secrets.MY_SECRET }}. Never echo them — GitHub masks automatically.
☸️ Kubernetes Probes — Health Checks
PROBEPURPOSEWHAT HAPPENS ON FAILURE
livenessProbeIs the container still alive? Detects deadlocks or stuck states.Container is restarted
readinessProbeIs the container ready to accept traffic? Warm-up time after start.Pod removed from Service endpoints (no traffic sent)
startupProbeFor slow-starting apps. Disables liveness + readiness until startup succeeds.Container restarted if startup takes too long
# In your deployment.yaml:
livenessProbe:
  httpGet: { path: /health, port: 3000 }
  initialDelaySeconds: 10  # wait 10s before first check
  periodSeconds: 5     # check every 5s
readinessProbe:
  httpGet: { path: /ready, port: 3000 }
☸️ Kubernetes RBAC
Role-Based Access Control — controls who can do what in Kubernetes. Same least-privilege principle as IAM.

Role — defines permissions within a namespace (e.g., "can get/list pods in namespace production").
ClusterRole — same as Role but cluster-wide (all namespaces).
RoleBinding — attaches a Role to a User/ServiceAccount/Group.
ServiceAccount — identity for pods. Pods can access the K8s API using their ServiceAccount's permissions (like IAM roles for pods).
💰 Cost Optimization in Cloud
Right-sizinginstance size
Match instance size to actual workload. t3.micro for low-traffic apps vs m5.2xlarge for compute-heavy. Use CloudWatch to see actual CPU/RAM utilization, then downsize.
Spot Instancesup to 90% cheaper
AWS sells spare capacity at huge discounts (up to 90%). Can be reclaimed with 2-min warning. Use for batch jobs, CI/CD runners, non-critical workers that can handle interruption.
Reserved Instances1-3 year commit
Commit to 1 or 3 years of usage → up to 72% discount. Use for stable, predictable baseline workloads (web servers, databases that always run).
Auto Scalingscale to zero
Scale down to minimum at night/weekends for dev/staging environments. HPA in K8s scales pods. ASG scales EC2 nodes. Only pay for what you use.
🔄 CI/CD Patterns — Advanced
Feature Flagstrunk-based
Ship code to production behind a flag that's turned off. Enable for specific users/% traffic. Enables trunk-based development — you can merge half-done features safely.
Error BudgetSRE concept
If SLO = 99.9% uptime, your error budget = 0.1% (8.7 hours/year). If you exhaust your budget, you freeze new features and focus on reliability. Balances velocity and stability.
Immutable Infrareplace not patch
Never patch a running server. Build a new one from scratch, deploy, destroy the old one. Eliminates configuration drift. Every server is identical to the last known good state.
12-Factor Appcloud-native design
Methodology for cloud-native apps. Key factors: store config in env vars, treat logs as streams, stateless processes, explicit dependencies. Enables easier containerization and scaling.
