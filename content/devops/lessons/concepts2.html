🏛️Microservices vs MonolithArchitecture
A microservice is an architectural style that structures an application as a collection of small, loosely coupled, and independently deployable services. Each service focuses on a specific business domain (e.g. auth service, payment service, notification service) and communicates with others through well-defined APIs.

A monolith is a single massive unit where all functions and services are interconnected and run as a single process. Simpler to build initially, but harder to scale and deploy independently.

DevOps angle: Microservices = more containers, more complexity for Kubernetes to manage. Each service can be deployed independently — one team can ship without waiting for others. Monoliths deploy as one unit — all or nothing.

⬅️Shift LeftDevOps Principle
The concept of "shift left" refers to the practice of performing tasks earlier in the software development lifecycle — moving quality, security, and testing activities to the left (earlier) on the timeline.

Traditionally, testing and security reviews happened at the end. Shift left means: write tests while you code, run security scans in CI, catch issues at commit time not at deployment time.

Why it matters: A bug found at commit time costs minutes to fix. The same bug found in production costs hours of downtime and potentially money. The earlier you catch it, the cheaper it is.

🏗️IaC — Infrastructure as CodeTerraform / CloudFormation / Ansible
IaC is the practice of managing and provisioning infrastructure through machine-readable configuration files rather than through physical hardware configuration or interactive tools (manual clicking).

By keeping infrastructure in code format:
• Stored in version control (Git) — full audit trail
• Automated deployment consistently across environments
• Reduces risk of human error
• Increases efficiency — one command spins up entire environment

No company owns physical servers — they rent from AWS, Azure, GCP. IaC defines exactly what you're renting and how it's configured.

🏠Self-Hosted CI/CD ToolsJenkins / GitLab CI
Some CI/CD tools can be installed on your own infrastructure — they don't require external internet access and you control everything.

Jenkins — the most popular self-hosted CI tool. Highly configurable via plugins. You run it on your own server. Great for companies with strict data policies.

GitLab CI/CD — built into GitLab. Can be entirely self-hosted. Pipeline defined in .gitlab-ci.yml. Integrated with code reviews, merge requests, and container registry all in one place.

vs Cloud CI/CD: GitHub Actions, CircleCI, and AWS CodePipeline run on the vendor's infrastructure — easier setup but your code leaves your servers.
