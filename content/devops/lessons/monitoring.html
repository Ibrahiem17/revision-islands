📊 Monitoring vs Logging
📈 Monitoring
Collecting data about current performance and stability. Is the system healthy right now? Is CPU at 90%? Are response times spiking?

• Infrastructure monitoring (CPU, RAM, disk, network)
• Application monitoring (error rates, latency, throughput)
• User experience monitoring (Apdex score, page load times)
📋 Logging
Collecting the historical record of what happened. What did the app do at 2:17 AM? What error did user X see?

• Log aggregation (ELK stack, Loki, CloudWatch Logs)
• Security analytics (who accessed what)
• Application errors and slow queries
🔥 Prometheus Deep Dive
📡PrometheusMetrics + Alerting
Pull-based: Prometheus scrapes metrics from targets on a schedule. Each target exposes a /metrics endpoint. Prometheus pulls every 15s.

Time-series database: Stores all metrics as timestamped values. Query "what was CPU at 3 AM last Tuesday?"

PromQL: Powerful query language. rate(http_requests_total[5m]) = request rate over 5 mins.

Alertmanager: Routes alerts to Slack/PagerDuty/email. Deduplicates and silences.

📊 Grafana
📊GrafanaVisualization + Dashboards
Connects to Prometheus (and 50+ other data sources) and turns raw data into dashboards. Drag-and-drop panels: graphs, gauges, heatmaps. Alert rules: "if error rate > 1%, notify Slack." Variables for dynamic dashboards (switch env: dev/staging/prod). Always deployed with Prometheus.

🚦 Rate Limiting — Two Algorithms
🪣 Token Bucket
Fixed tokens replenished at fixed rate. Each request consumes a token. Empty bucket = rejected. Allows bursts up to bucket size.
💧 Leaky Bucket
Requests leak out at a constant rate. Bucket overflows = dropped. Smooths bursts — output rate is always constant.
