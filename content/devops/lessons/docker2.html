🔐 Docker Security Best Practices
Run as non-rootcritical
Default: containers run as root. If the container is compromised, the attacker has root on the host. Always add a USER instruction in your Dockerfile.
RUN adduser --disabled-password appuser USER appuser
Use specific tagscritical
Never use FROM node:latest in production. A new "latest" push can break your build silently. Pin exact versions: FROM node:18.17.1-alpine3.18 for reproducible, auditable builds.
.dockerignoreimportant
Exclude files from the Docker build context: node_modules, .git, .env, test files, docs. Smaller build context = faster builds + no accidental secret inclusion.
.git node_modules .env *.test.js README.md
Scan imagesimportant
Use docker scout cves myapp:latest or Trivy/Snyk to scan images for CVEs (known vulnerabilities). Run in CI — block deploys if critical vulns are found.
$ trivy image myapp:v2.0 $ docker scout cves myapp:latest
Resource limitsgood practice
Without limits, one container can consume all host resources and starve others. Set memory and CPU limits on every container in production.
$ docker run --memory="512m" --cpus="0.5" myapp # K8s: resources.limits.memory: 512Mi
Distroless imagesgood practice
Images with no shell, no package manager, no OS utilities — only your app + its runtime. Dramatically smaller attack surface. Google Distroless, Alpine, scratch. Use in final stage of multi-stage builds.
🏥 Docker HEALTHCHECK
# In Dockerfile — Docker monitors container health
HEALTHCHECK --interval=30s --timeout=5s --retries=3
  CMD curl -f http://localhost:3000/health || exit 1

# Docker marks container: healthy / unhealthy / starting
docker ps                 # shows (healthy) or (unhealthy) status
docker inspect --format='{{json .State.Health}}' <id>
📦 ARG vs ENV — Build vs Runtime
ARG — Build-time only
Available only during docker build. NOT in the running container. Pass with --build-arg.

Use for: build-time configs (Node version, build flags). Not for secrets — ARG values are visible in image history.
ARG NODE_VERSION=18 FROM node:${NODE_VERSION}
ENV — Runtime variable
Available in the running container. Persists into the image. Set at build time, accessible at runtime.

Use for: NODE_ENV=production, app configs. Override at docker run -e KEY=val. Still not for secrets — use secrets manager.
🌐 Docker Networking Deep Dive
# Create a custom network — containers communicate by name
docker network create mynet
docker run --network mynet --name db postgres
docker run --network mynet --name app myapp
# app container can reach db with hostname "db"

# Port mapping: host:container
docker run -p 8080:3000 myapp   # host:8080 → container:3000
docker run -p 127.0.0.1:8080:3000 myapp # bind only to localhost
📋 Container Logging
DRIVERWHERE LOGS GO
json-file (default)JSON files on the host. Accessible via docker logs. Can fill disk if not rotated.
awslogsShips directly to AWS CloudWatch Logs. Standard for ECS tasks.
fluentdShips to Fluentd/Fluent Bit → ELK or any aggregator. Standard for K8s.
💡 12-Factor principle: Treat logs as streams. Apps should write to stdout/stderr. The container runtime or an agent collects and ships them. Never write log files inside a container.
