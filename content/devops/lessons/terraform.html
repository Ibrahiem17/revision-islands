⚙️ Terraform Workflow
1
Configuration FilesHCL / JSON
Define your infrastructure using .tf files written in HCL (HashiCorp Configuration Language) or JSON. Describe servers, networks, databases — everything as code.
main.tfvariables.tfoutputs.tf
2
Execution Planterraform plan
Terraform generates a plan showing exactly what will be created, changed, or destroyed to reach the desired state. Review before applying — no surprises.
terraform initterraform plan
3
Resource Provisioningterraform apply
Terraform applies the plan — provisions and configures all the resources. Creates EC2 instances, VPCs, S3 buckets, whatever you defined.
terraform apply
4
State Managementterraform.tfstate
Terraform tracks current infrastructure state in a state file. This is how it knows what exists and what needs to change. In teams, store state in a remote backend (S3 + DynamoDB lock) — never commit it to Git.
5
Version ControlGit
Store configuration files in Git. Review infra changes via PRs. Full audit trail. Never hardcode secrets — use environment variables or a secrets manager.
🌐 Multi-Cloud with Terraform
1. Define Providers — add provider blocks for each cloud (AWS, Azure, GCP). Each configures how Terraform interacts with that cloud.
2. Resource Definitions — define resources per cloud in the same or separate .tf files.
3. Remote State — use a remote backend (S3, Azure Blob) to share state across team members. Critical for multi-cloud consistency.
4. Networking — configure VPCs, VPNs, or VPC peering for cross-cloud communication.
5. Authentication — use environment variables or a secrets manager for cloud credentials. Never hardcode access keys.

⚔️ Terraform vs Ansible — They're Teammates, Not Rivals
The golden rule: Use Terraform to build the house. Use Ansible to arrange the furniture.
🏗️ Terraform — Provisioning
Best for: Managing the lifecycle of infrastructure itself — VPCs, EC2 instances, S3 buckets, RDS, load balancers.

Declarative: You describe the end state ("I want 5 servers"). Terraform figures out how.

State-aware: Keeps a .tfstate file. Knows exactly what exists. If you manually delete something, Terraform sees the "drift" and recreates it.

Immutable: Change a server's size? Terraform destroys the old one and creates a new one. Prevents config drift.
⚙️ Ansible — Configuration Management
Best for: Configuring the software inside servers once they exist — installing Nginx, updating packages, managing users, deploying app code.

Procedural: Follows a playbook step-by-step. Like running shell commands across 100 servers at once.

Stateless: Doesn't track infra in a database. Logs into target, checks state, applies changes. If you delete a server, Ansible won't know until it tries to reach it.

Agentless: No agent to install on target servers. Just SSH.
