🏛️ Core Architecture
🧠 Control Plane (Master Node)
Controls everything in the cluster:

API Server — entry point for all commands. Every kubectl command hits this.
Scheduler — decides which worker node a new pod should run on.
Controller Manager — watches cluster state, makes sure reality matches desired state.
etcd — the cluster's database. Stores all state. If etcd dies, cluster is blind.
⚙️ Worker Nodes
Runs actual applications:

Kubelet — agent on every worker node. Talks to the control plane, ensures pods are running.
Container Runtime — Docker (or containerd). Actually runs the containers.
Pods — the actual workloads run here. One or more containers per pod.
📦 The 8 Objects You Must Know
OBJECTWHAT IT DOES
PodSmallest deployable unit. Wraps one or more containers sharing network and storage. Usually 1 container per pod. Pods are ephemeral — they die and get new IPs.
DeploymentManages desired state: "I want 3 replicas of this pod." K8s creates/kills pods to match. Handles rolling updates. Use for stateless apps (APIs, web servers).
StatefulSetLike Deployment but for stateful apps. Pods get stable names (pod-0, pod-1). Persistent volume per pod. Use for databases, Kafka, Zookeeper.
ServiceStable network endpoint in front of pods. Pods die and get new IPs — the Service IP never changes. 3 types: ClusterIP (internal), NodePort (node IP), LoadBalancer (external).
IngressExternal HTTP/HTTPS routing into the cluster. Path-based rules: /api → backend, / → frontend. One entry point instead of many LoadBalancers. Needs an Ingress Controller (Nginx).
ConfigMapInject non-sensitive config into pods (env vars, config files). Decouples config from image — change config without rebuilding the image.
SecretLike ConfigMap but for sensitive data (passwords, tokens). Base64-encoded — NOT encrypted by default. Use sealed secrets or external secret managers in prod.
NamespaceLogical isolation within one cluster. Separate dev, staging, prod environments. Set resource quotas per namespace.
HPAHorizontal Pod Autoscaler. Auto-scales replicas based on CPU % or custom metrics. K8s watches load and adds/removes pods automatically.
🔑 Service Types
TYPEUSE CASE
ClusterIPInternal communication only. Default type. Service is only reachable from inside the cluster. Use for internal microservice-to-microservice calls.
NodePortExposes service on a static port on every node's IP. Reachable from outside via NodeIP:port. Simple but not production-grade.
LoadBalancerCreates a cloud provider load balancer (AWS ALB, etc.). Gives you an external IP. Production way to expose services. Use Ingress to avoid one LB per service.
🔧 Deployment vs StatefulSet
Deployment — Stateless Apps
Any replica is identical. Easy rolling updates built-in. Easy scale up/down.

Use for: APIs, web servers, workers, anything where one pod = any other pod.
StatefulSet — Stateful Apps
Pods get stable names: pod-0, pod-1, pod-2. Each pod gets its own Persistent Volume.

Use for: Databases, Kafka, Zookeeper — apps that care about identity and data.

📦 Helm — Kubernetes Package Manager
Helm is the package manager for Kubernetes — like npm for Node. Instead of writing raw YAML for every resource, you use a Helm chart — a reusable, parameterized template.

helm install myapp ./chart — deploys everything in one command.
helm upgrade myapp ./chart — rolls out changes.
helm rollback myapp 1 — rollback to revision 1.

Public charts available at Artifact Hub for common tools (nginx, prometheus, postgres, etc.)
🔄 Persistent Volumes (Stateful Apps)
PV (Persistent Volume) — storage resource provisioned in the cluster (an actual disk).
PVC (Persistent Volume Claim) — a pod's request for storage. "I need 10GB." K8s binds it to a matching PV.

This decouples storage from the pod lifecycle. When a pod dies and is recreated, it reattaches to the same PVC — data is still there. Essential for databases in Kubernetes.

The K8s DevOps Flow
Build Docker image → Push to registry → Deploy using Kubernetes YAML (kubectl apply) → K8s schedules pods on worker nodes → Service exposes them → Ingress routes external traffic → HPA scales on load.
🔄 How a Deploy Actually Works — Step by Step
1
kubectl apply -f app.yaml
You send the request. Goes to the API Server — the single entry point for everything in K8s.
2
Stored in etcd
Desired state saved: "Run 3 pods of this image." etcd is the cluster's source of truth.
3
Scheduler decides
Scheduler looks at available worker nodes and chooses the best one for each pod (resources, taints, affinity rules).
4
Workers execute
Kubelet on the assigned node receives the instruction. Container runtime pulls the image and starts the container. Pods are now running.
5
Continuous monitoring
Controller Manager watches. If a pod crashes, it creates a new one immediately. Desired state = reality at all times. This is self-healing.

🔥 Debug a Failing Pod — The Interview Flow
Step 1: kubectl get pods — is the pod Running, Pending, CrashLoopBackOff, or Error?
Step 2: kubectl describe pod <name> — check Events section at the bottom. Most answers are here (image pull fail, OOM killed, liveness probe fail).
Step 3: kubectl logs <pod> — read the application's own error output.
If pod won't start: Image name wrong? Resources exceeded? ConfigMap/Secret missing? Node has space?
If pod keeps crashing: CrashLoopBackOff = app crashes on startup. Check logs immediately after start: kubectl logs <pod> --previous
📦 More K8s Workload Types
TYPEWHAT IT DOES
DaemonSetRuns exactly one pod on every node. When a new node joins the cluster, the pod is automatically added. Use for: log collectors (Fluentd), monitoring agents (Prometheus node-exporter), network plugins. Can't scale — always = number of nodes.
JobRuns a pod to completion (not indefinitely). Pod runs, completes its task, exits with code 0. Use for: database migrations, batch processing, one-off scripts. Retries on failure.
CronJobLike a Kubernetes-native cron job. Creates a Job on a schedule. schedule: "0 2 * * *" = daily at 2 AM. Use for: nightly reports, cleanup tasks, backups.
initContainerRuns before the main container starts. Completes then exits. Use for: run DB migrations before app starts, wait for a dependency to be ready, copy config files.
⚙️ Resource Requests vs Limits
Requests — the amount K8s reserves for the pod. Scheduler uses this to decide which node has enough capacity.
Limits — the maximum the pod can consume. If it exceeds CPU limit, it's throttled. If it exceeds memory limit, it's OOMKilled.

Always set both. No requests = scheduler can't plan. No limits = one bad pod can starve all others on the node.
resources:
  requests:
    memory: "256Mi"  # reserved
    cpu: "250m"     # 0.25 cores reserved
  limits:
    memory: "512Mi"  # OOMKilled if exceeded
    cpu: "500m"     # throttled if exceeded
🚧 Taints, Tolerations & Node Affinity
Taint & Toleration
Taint — mark a node as "not for general use." Only pods with a matching toleration can be scheduled there.

Use case: Dedicate GPU nodes only to ML workloads. Taint the GPU node. Only ML pods tolerate it.
Node Affinity
Schedule pods preferring or requiring specific nodes based on labels. Less strict than taints — you express preference, not exclusion.

Use case: "Schedule payment service pods on nodes in us-east-1a only."

📦 Resource Requests & Limits — CRITICAL
Requests — what the container is guaranteed. The Scheduler uses this to decide which node has enough capacity for the pod.
Limits — the maximum the container can use. If it exceeds the memory limit, it gets OOMKilled. If it exceeds CPU limit, it gets throttled (not killed).
resources:
  requests:
    memory: "128Mi"       # guaranteed RAM
    cpu: "250m"           # guaranteed CPU (250 millicores = 0.25 CPU)
  limits:
    memory: "512Mi"       # max RAM — exceed this → OOMKilled
    cpu: "1000m"          # max CPU — exceed this → throttled (not killed)
🔢 More K8s Objects You'll Be Asked About
OBJECTWHAT IT DOES
DaemonSetEnsures one pod runs on every node in the cluster. Use for: log collectors (Fluentd), monitoring agents (node-exporter), network plugins. When a new node joins, DaemonSet automatically schedules a pod on it.
JobRuns one or more pods to completion. Pod must finish successfully, then the Job is done. Use for: database migrations, batch processing, one-off tasks. Unlike Deployment, pods are not restarted after success.
CronJobRuns a Job on a cron schedule. schedule: "0 2 * * *" = daily at 2 AM. Use for: nightly backups, scheduled reports, cache warming.
Init ContainerRuns before the main app container starts. Must complete successfully. Use for: wait until DB is ready, download config files, set up permissions. Multiple init containers run sequentially.
SidecarA second container in the same pod as the main app. Shares network + storage. Use for: log shippers, service mesh proxies (Envoy/Istio), secret injection, monitoring agents.
NetworkPolicyControls which pods can talk to which pods. By default, all pods can talk to all pods. NetworkPolicy lets you say "only the frontend service can talk to the API service on port 3000." Needs a CNI plugin that supports it (Calico, Cilium).
🎯 Taints, Tolerations & Node Affinity
Taints & Tolerations
Taint a node to repel pods: kubectl taint nodes gpu-node gpu=true:NoSchedule

Pods won't be scheduled there UNLESS they have a toleration for that taint. Use for: dedicating GPU nodes only to ML workloads, isolating production nodes.
Node Affinity
Attract pods to specific nodes based on labels. Softer than taints — "prefer to run on SSD nodes" or "must run on us-east-1a nodes".

nodeSelector is the simpler version: only schedule this pod on nodes with label disktype=ssd.
