⚙️ GitHub Actions — Key Keywords
KEYWORD WHAT IT DOES
nameDisplay name for the workflow or step. Shows in GitHub Actions UI.
onTrigger — what event starts the workflow. push, pull_request, schedule, workflow_dispatch
jobsTop-level grouping. A workflow has multiple jobs. Jobs run in parallel by default.
runs-onWhich runner (machine) to use. ubuntu-latest, windows-latest, macos-latest
stepsOrdered list of tasks within a job. Run sequentially top to bottom.
runShell command to execute. run: npm test, run: docker build .
usesUse a pre-built action. uses: actions/checkout@v3, uses: docker/login-action@v2
withInput parameters for a uses action. Key-value pairs passed to the action.
envSet environment variables. Can be at workflow, job, or step level.
needsJob dependency. needs: build means this job waits for 'build' job to succeed first.
📄 Example GitHub Actions Workflow
# .github/workflows/ci.yml
name: CI Pipeline

on:
  push:
    branches: [main, develop]
  pull_request:

jobs:
  build-and-test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      - name: Install deps
        run: npm install
      - name: Run tests
        run: npm test
  deploy:
    needs: build-and-test # waits for above
    runs-on: ubuntu-latest
    steps:
      - name: Build Docker image
        run: docker build -t myapp .
📄
Pipelines automate: Build → Test → Deploy
Workflow = the whole file. | Trigger (on) = what starts it. | Jobs = parallel work units. | Steps = sequential commands inside a job. | needs = job ordering.
